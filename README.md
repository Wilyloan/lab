# lab

Консольная утилита для лабораторных работ по C: создаёт шаблоны, собирает,
запускает функциональные тесты и форматирует код. Права администратора (sudo)
не нужны.

## Установка

```bash
git clone <адрес-репозитория>
cd <папка-репозитория>
./install.sh
```

После установки откройте новый терминал.


## Использование

Перейдите в папку, где лежат (или будут лежать) лабораторные, и запустите:

```bash
lab
```

Все папки и файлы создаются в текущей папке.

| Пункт | Что делает |
|---|---|
| 1 | Создать шаблон лабораторной |
| 2 | Список лабораторных в текущей папке |
| 3 | Собрать лабораторную (gcc) |
| 4 | Запустить функциональные тесты |
| 5 | Создать `.gitignore` в текущей папке |
| 6 | Отформатировать код лабораторной |
| 0 | Выход |

## Шаблон лабораторной

Папка называется `lab_LL_PP_CC` (лабораторная, задача, вариант) или `lab_LL_PP`,
если задача общая и без вариантов.

```
lab_01_02_03/
├── main.c
└── func_tests/
    ├── README.md
    └── data/
        ├── pos_01_in.txt     входные данные позитивного теста
        ├── pos_01_out.txt    вывод программы (записывается при запуске тестов)
        ├── pos_01_args.txt   аргументы командной строки (необязательно)
        ├── neg_01_in.txt
        ├── neg_01_out.txt
        └── neg_01_args.txt
```

При создании можно выбрать количество позитивных и негативных тестов и
количество файлов с аргументами (по умолчанию 3, 3 и 0).

## Функциональные тесты

Для каждого `*_in.txt` программа запускается с аргументами из `*_args.txt`
(нет файла или он пуст — без аргументов), а её вывод записывается в `*_out.txt`.

- **Позитивный тест** пройден, если код возврата равен `0`.
- **Негативный тест** пройден, если код возврата не равен `0`.
- Аварийное завершение (segfault, abort и т. п.) считается провалом.
- Тест, выполняющийся дольше 5 секунд, считается провалом.

В файле аргументов они разделяются пробелами или переводами строк; в кавычках
(`"..."`, `'...'`) можно передать аргумент с пробелами.

Сборка: `gcc -std=c99 -Wall -Wextra -Werror` (флаги задаются в начале файла
`lab`, переменная `CFLAGS`).

## Форматирование

Пункт 6 запускает `clang-format` для `.c` и `.h` файлов выбранной лабораторной.


Форматтер ищется в таком порядке: `tools/clang-format`, установленный
`lab-clang-format`, расширение «C/C++» для VS Code, `clang-format` из системы.

Форматирование не исправляет имена, комментарии и объявления переменных, их
нужно проверять вручную.

Так, например:
```c
#include <stdio.h>
#include <math.h>
#define max 10
```
Произойдет ошибка во внутренних тестах по двум причинам:
1) Нет пустой строки между блоками `#define` `#include` (Форматтер директивы не трогает)
2) регистр букв в макросе всегда должен быть верхним 
Форматтер НЕ ИСПРАВИТ это. 

## Требования

- gcc
